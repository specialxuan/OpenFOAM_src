## 概述

`fastDynamicFvMesh` 采用模态叠加方法驱动网格运动。每次 `update()` 的主流程如下：

1. 在 `fsiPatches` 上计算压力力与剪切力。
2. 将面力投影到模态坐标，得到 `modeForce_`、`modePressureForce_`、`modeShearForce_`。
3. 对模态力做力松弛，计算并更新 `fsiResidual_`。
4. 使用 Wilson-Theta 方法积分模态动力学，更新位移/速度/加速度。
5. 将模态位移增量重建到网格点，调用 `movePoints()` 更新网格。
6. 在写出时刻写全局模态状态文件，支撑重启。

该实现支持：

- 压力场维度兼容（`dimPressure` 或运动学压力 `dimPressure/dimDensity`）。
- 压力和剪切分量分别统计。
- 并行归约与重启续算。

## 构建与安装

在已 source OpenFOAM 环境后，在仓库根目录执行：

```bash
wmake libso fastDynamicFvMesh
```

或进入库目录执行：

```bash
cd fastDynamicFvMesh
wmake libso
```

在 `system/controlDict` 中加载库：

```foam
libs ("libfastDynamicFvMesh.so");
```

在 `constant/dynamicMeshDict` 中指定：

```foam
dynamicFvMesh fastDynamicFvMesh;
```

## 运行流程（高层）

- 构造函数阶段：
  - `readControls()` 读取参数。
  - `readModeShapes()` 读取 `mode` 目录中的模态数据并构建点映射。
  - `buildForceProjectionCaches()` 预计算面-模态投影缓存。

- 每个时间步 `update()` 阶段：
  - `calcModalForces()`：计算当前流体载荷对应的模态力。
  - 力松弛：`appliedModeForce_ = old + alpha*(raw-old)`。
  - `solveStructuralDynamics(dt)`：推进模态状态。
  - 位移限制：`|dDisp|` 超过 `maxDispChange_` 时截断。
  - `movePoints(newPoints)`：更新网格。
  - `writeDiagnostics()`（可选）写 `modal_diagnostics.csv`。
  - `writeTime()` 时主进程写全局模态状态文件。

## 配置文件说明（dynamicMeshDict）

在 `constant/dynamicMeshDict` 的 `fastDynamicFvMeshCoeffs` 中可配置：

- `theta`：Wilson-Theta 参数，默认 `1.4`。
- `fsiPatches`：FSI patch 名称列表，必填且至少一个。
- `mappingTolerance`：CSV 节点映射到网格点的距离容差。
- `couplingRelaxation`：力松弛系数，范围 `(0,1]`。
- `pressureField`：压力场名，默认 `p`。
- `rhoRef`：运动学压力下的参考密度（若未提供，可从 `transportProperties` 的 `rho` 或场 `rho` 获取）。
- `pRef`：压力参考值（计算压力力时使用 `(scale*p - pRef)*Sf`）。
- `maxDispChange`：单次更新允许的模态位移增量上限。
- `modalMass`：各模态质量数组（长度必须等于模态数；缺省为全 1）。
- `modalDamp`：各模态阻尼数组（长度必须等于模态数；缺省为全 0）。
- `writeDiagnostics`：是否写 `modal_diagnostics.csv`（默认 `false`）。
- `trackTiming`：是否记录流体/网格 CPU 计时（默认 `false`）。

约束与检查：

- `couplingRelaxation` 不在 `(0,1]` 会报错退出。
- 若显式提供了 `rhoRef`，则必须大于 0。
- `fsiPatches` 缺失或为空会报错退出。
- `modalMass` / `modalDamp` 长度与 `nMode` 不一致会报错退出。

## 输入/输出文件

### 输入（`mode` 目录）

- `FluidNodeCoor.csv`：节点坐标，首行应包含节点数和模态数信息。
- `FluidNodeDisp1.csv ... FluidNodeDispN.csv`：逐模态位移文件，每个文件首行包含频率（可附带节点数/模态数校验信息）。
- `FluidPara.csv`（可选）：读取 legacy 初始速度；缺失时初始速度为 0。

### 输出

- `modal_diagnostics.csv`（`writeDiagnostics=true` 时）：
  - 列为：`Time`、`Force_i`、`PressureForce_i`、`ShearForce_i`、`Disp_i`、`Vel_i`、`Acc_i`、`AppliedDisp_i`。

- 每个写出时刻在 case 根目录时间文件夹下写入：
  - `modeState`
  - `modeForce`
  - `appliedModeDisp`
  - `appliedModeForce`

这些文件用于重启恢复模态状态。

## 核心数据结构与成员变量

- 模态状态：
  - `IOField<vector> modeState_`：每模态 `(disp, vel, acc)`。
  - `scalarField modeForce_`：当前模态力。
  - `scalarField modeForce0_`、`List<vector> modeState0_`：上一步状态。
  - `IOField<scalar> appliedModeDisp_`：实际施加到网格的模态位移。
  - `IOField<scalar> appliedModeForce_`：力松弛后的模态力。

- 力分解：
  - `modePressureForce_`：压力贡献。
  - `modeShearForce_`：剪切贡献。

- 几何与缓存：
  - `fsiPatchIDs_`、`fsiPolyPatches_`：FSI patch 缓存。
  - `faceModeProjection_[patch][mode][face]`：面-模态投影缓存。
  - `pressureScaleCache_`：每 patch 的压力缩放缓存。

- 计时：
  - `trackTimingEnabled_`、`timingFluidCpuAccum_`、`timingMeshCpuAccum_` 等。

- 其他：
  - `fsiResidual_`：当前 FSI 力残差（并写入对象 `fsiResidual`）。
  - `lastGlobalWriteTimeIndex_`：防止同一物理时间重复写全局状态。

## 关键函数说明

### `readControls()`

读取并校验 `fastDynamicFvMeshCoeffs`。缺字段或非法参数会 `FatalError` 退出。

### `readModeFiles()` 与 `readModeShapes()`

- 在主进程读 CSV，再广播到并行进程。
- 映射时优先读取 `constant/polyMesh/points` 作为基准点（避免重启时用已变形点导致映射偏差）。
- 采用最近邻 + `mappingTolerance` 映射，映射只在启动时做一次。

### `buildForceProjectionCaches()`

对每个 FSI patch、每个模态、每个面预计算平均形函数向量，减少每步重复计算。

### `cacheModelPointers()`

缓存湍流/热物性/层流模型指针，避免每步重复查表。

### `calcModalForces()`

- 清零模态力数组。
- 读取压力场并检查维度。
- 计算各面压力力与剪切力。
- 用缓存的 `faceModeProjection_` 做投影累加。
- 并行下对每个模态做 `reduce(sumOp<scalar>())` 归约。

### `solveStructuralDynamics(dt)`

按 Wilson-Theta 公式更新每模态 `dis/vel/acc`。

### `update()`

- 先计时（可选），识别是否同一物理时间的第一次调用。
- 计算模态力并执行力松弛，更新 `fsiResidual_`。
- 启动前两步使用初始化逻辑；随后正常推进结构动力学。
- 用 `dDisp` 更新网格，并执行位移增量限幅（`maxDispChange_`）。
- 写诊断（可选）并在写出时刻写全局状态文件。

## 并行与重启机制

- 并行时，`calcModalForces()` 先本地累加，再逐模态 `reduce`。
- 写出时刻仅主进程在全局路径写 `modeState/modeForce/appliedModeDisp/appliedModeForce`。
- 重启时若读到有效 `modeState_`（尺寸与 `nMode_` 一致），将直接进入续算路径：
  - `startupStepCount_` 置为已完成初始阶段；
  - `modeState0_`、`modeForce0_` 由读入值初始化；
  - 若 `appliedModeDisp_` 缺失，按 `modeState_.x()` 初始化，避免重复施加位移。

## 计时输出说明

当 `trackTiming=true` 且到达 `writeTime()`，主进程输出：

`FSI timing [CPU s] at t=... step{fluid=..., mesh=..., total=...} cumulative{...}`

含义：

- `fluid`：两次 `update()` 之间的 CPU 时间估计（流体求解阶段）。
- `mesh`：`update()` 内部耗时（网格更新阶段）。
- `step`：本写出区间增量。
- `cumulative`：从运行开始累计。

## 故障排查与调优建议

- 映射点为 0：
  - 检查 `FluidNodeCoor.csv` 坐标系/单位；
  - 增大 `mappingTolerance`；
  - 确认使用的基准网格与模态坐标一致。

- `Pressure field ... was not found`：
  - 检查 `pressureField` 命名与求解器字段一致。

- 运动学压力但密度缺失：
  - 在 `dynamicMeshDict` 给 `rhoRef`，或提供 `transportProperties` 中 `rho`，或提供 `rho` 场。

- 模态响应过激或振荡：
  - 适当降低 `couplingRelaxation`；
  - 检查 `modalMass/modalDamp` 是否合理；
  - 视情况收紧 `maxDispChange`。

- 运行慢：
  - 先开启 `trackTiming` 看 fluid/mesh 时间占比；
  - 模态映射慢通常只在启动阶段；步进阶段重点看网格规模与模式数。
